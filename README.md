# قرطاج — آخر يوم في قرطاج

## مصدر المشروع

- `index.html`: التطبيق الأصلي والقصة التفاعلية. هذا الملف يملك النصوص، الفصول، القرارات، حالة اللعب والحفظ.
- `scripts/prepare-web.cjs`: تجهيز نسخة الويب الخاصة بـ Android وحقن إضافات QARTON والحفظ والتشخيص.
- `scripts/qarton-main-tree.js`: واجهة QARTON الرئيسية ومسار الانتقال إلى القصة.
- `scripts/qarton-premium-home.js`: تنسيق شاشة React الأصلية وقفل/تحرير مساحة الشاشة.
- `scripts/carthage-cinematic-adapter.mjs`: محوّل المحرك السينمائي؛ لا يبدأ مشهداً تلقائياً.
- `www/`: ملفات مولّدة أثناء التجهيز، وليست مصدر التعديل اليدوي.

لا نعدّل القصة أو اللهجة التونسية أو بنية الحفظ أثناء أعمال الواجهة والمحرك إلا بطلب صريح.

## بيئة التطوير

يتطلب المشروع Node.js 22 أو أحدث.

```bash
npm install
npm test
npm run prepare:web
```

لمعاينة نسخة QARTON المجهزة عبر المتصفح، شغّل خادماً محلياً على مجلد `www/` بعد `npm run prepare:web`. فتح `index.html` مباشرة من مدير الملفات يعرض مصدر اللعبة الأصلي ولا يضمن تشغيل إضافات QARTON التي تُحقن أثناء التجهيز.

## Android

- معرّف التطبيق: `com.qarton.carthage`.
- مجلد الويب الذي يعبّئه Capacitor: `www`.
- أمر المزامنة: `npm run android:sync`.
- بناء APK والتحقق من الحزمة يتمان عبر GitHub Actions.
- لا تمسح بيانات التطبيق أو تستبدل النسخة المثبتة قبل التحقق من نسخة الحفظ.

## حالة QARTON الحالية

- واجهة الشجرة الرئيسية تعمل كطبقة منفصلة وتستدعي أزرار React الأصلية بدلاً من استنساخها.
- مسار اللعبة الجديدة يبدأ بمقدمة من خمس خطوات قبل ظهور مؤقّت اللعب؛ لذلك يجب اعتبار شاشة المقدمة جزءاً من القصة النشطة وعدم انتظار `.game-timer` وحده.
- اختبارات العقد تتحقق من الانتقال بين القائمة والمقدمة واللعب، ومن عدم إدخال أدوات الحفظ داخل شاشة المقدمة.
- تكامل المحرك السينمائي في هذه المرحلة يسجل المحوّل فقط. لم يتم بعد تفعيل مشهد من المحرك داخل القصة، ولا توجد أصول سينمائية محلية معتمدة في هذا الفرع.

## قواعد الحفاظ على المشروع

1. لا تغيّر نصوص القصة أو ترتيب الفصول أو اللهجة أو الشخصيات دون طلب صريح.
2. لا تغيّر مفاتيح الحفظ أو مخططه دون اختبار ترحيل واسترجاع.
3. لا تجعل واجهة QARTON تملك حالة React أو تنسخ عناصر React؛ استخدم جسوراً واضحة إلى المعالجات الأصلية.
4. كل إضافة DOM يجب أن تملك دورة حياة محددة، وأن تُزال عند مغادرة الشاشة التي تخصها.
5. لا تفعّل مشهداً سينمائياً جديداً قبل اختبار التحميل والتنظيف والحفظ والحركة المخفّضة على Android فعلياً.
6. لا تدمج فرع التطوير في `main` قبل نجاح CI واختبار الهاتف وموافقة صاحب المشروع.
