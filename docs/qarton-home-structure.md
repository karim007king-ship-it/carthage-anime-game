# QARTON — آخر يوم في قرطاج
## مواصفات الشاشة الرئيسية المعتمدة

الحالة: توثيق للبنية المنفذة حالياً على فرع التطوير، وليس اقتراحاً لتغيير القصة أو منطقها.

## القرارات البصرية
- البنية: جذر رئيسي واحد للشاشة #qarton-main-tree.
- الطابع: hybrid؛ هوية قرطاجية ذهبية وحمراء فوق خلفية كحلية داكنة.
- عرض الوظائف: أربع بطاقات cards في شبكة 2×2.
- اتجاه النص عربي RTL، مع مراعاة الحواف الآمنة وارتفاعات الهواتف القصيرة.
- القائمة الرئيسية لا تحتاج إلى تمرير؛ القوائم الفرعية الطويلة تستخدم منطقة تمرير مستقلة.
- احترام إعداد prefers-reduced-motion.

## شجرة الشاشة الفعلية

    #qarton-main-tree
    ├── .qt-brand
    │   ├── .qt-mark
    │   └── .qt-word
    ├── .qt-title
    ├── .qt-summary
    ├── .qt-grid
    │   ├── card: القصة
    │   ├── card: عالم قرطاج
    │   ├── card: التقدم والحفظ
    │   └── card: الإعدادات
    └── .qt-footer

المشاهد الفرعية:
- القصة: أزرار اللعبة الأصلية لبداية جديدة والأجزاء المتاحة.
- عالم قرطاج: دليل قراءة للشخصيات والأماكن.
- التقدم والحفظ: متابعة آخر حفظ والتصدير والاستيراد الأصليان.
- الإعدادات: عناصر الصوت الأصلية فقط.

## قواعد الربط والسلوك
1. لا تُنسخ عناصر React الأصلية ولا تُنقل من أماكنها؛ أزرار QARTON تنادي معالجات العناصر الأصلية وقت الضغط.
2. قبل تنفيذ بداية جديدة أو فتح جزء، تُخفى طبقة QARTON مؤقتاً وتظهر واجهة اللعبة الأصلية حتى تبقى رسائل التأكيد مرئية.
3. زر متابعة آخر حفظ وأدوات النسخ الاحتياطي موجودة في «التقدم والحفظ» فقط.
4. دليل «عالم قرطاج» للقراءة ولا يغير الوقت أو الحالة أو التقدم.
5. لا تنشئ واجهة الإعدادات عناصر تحكم غير موجودة في اللعبة الأصلية.
6. عند بدء اللعب، تُزال واجهة القائمة وتُفصل مراقباتها حتى لا تعمل أثناء المشاهد.
7. لا تقرأ واجهة QARTON مفاتيح الحفظ ولا تعدل مخطط البيانات.

## دورة حياة الواجهة
- ينتظر runtime ظهور #root قبل التركيب.
- يراقب تغييرات الأبناء ونصوص الأزرار، وتغييرات `disabled` و`id` فقط لتحديث توفر الخيارات عند تبدّل حالة الفصول؛ لا يراقب كل أصناف CSS أو تغييرات التنسيق.
- عند بدء اللعب، يفصل المراقب ويزيل الغلاف ويعيد إظهار عناصر اللعبة الأصلية.
- أداة qarton-home-inspector.js تشخيصية لقياس تخطيط الشاشة، وليست جزءاً من منطق القصة.

## اختبارات القبول
- ظهور أربع بطاقات مستقلة في شبكة 2×2.
- عدم اعتماد تركيب القائمة على أسماء أصناف القائمة القديمة.
- انتقال كل بطاقة إلى القسم الصحيح.
- عمل بداية جديدة والأجزاء والمتابعة والتصدير والاستيراد عبر عناصر اللعبة الأصلية.
- عدم تكرار زر متابعة آخر حفظ في قسم القصة.
- عدم لمس مخطط الحفظ أو مفاتيح التخزين من runtime الواجهة.
- تحرير مراقبات الواجهة عند بداية اللعب.
- نجاح npm test، ثم نجاح بناء APK وفحص ملف HTML المعبأ.
- اختبار التفاعل الفعلي على الهاتف مطلوب قبل اعتماد APK؛ نجاح CI وحده لا يثبت سلوك اللمس داخل WebView.

## ملفات التنفيذ
- scripts/qarton-main-tree.js: بناء الشجرة والتنقل ودورة حياة الواجهة.
- scripts/qarton-premium-home.js: توافق/تحسين القائمة القديمة، ويجب عدم حذف قواعد CSS المتراكمة قبل اختبار تأثيرها.
- scripts/qarton-home-inspector.js: قياس تشخيصي للواجهة.
- scripts/prepare-web.cjs: حقن runtime وتجهيز نسخة Android؛ أي تعديل فيه يحتاج اختبارات الحفظ والتصدير والاستيراد.
- tests/qarton-main-tree-test.cjs: عقود بنية الشاشة والربط الآمن.
