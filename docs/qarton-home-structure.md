# QARTON — آخر يوم في قرطاج
## مواصفات هيكل الشاشة الرئيسية

الحالة: **تم فصل عرض HOME عن قائمة React القديمة** على مستوى واجهة QARTON؛ بقي التحقق على CI وجهاز Android فعلي قبل اعتماد APK.

## القرارات المعتمدة
- البنية: `main` بنظام شجرة واضح؛ جذر مستقل للشاشة الرئيسية.
- الطابع: `hybrid` يجمع الهوية القرطاجية مع إخراج أنمي سينمائي.
- الأقسام: بطاقات واضحة قابلة للمس.
- الهوية: QARTON — قرطون، ذهبي ملكي + أحمر عميق + أسود/كحلي.
- الشاشة الرئيسية ثابتة على ارتفاع نافذة الهاتف ولا تقبل التمرير الرأسي.
- مشاهد القصة تبقى قابلة للتمرير عند الحاجة؛ قفل التمرير يطبق على HOME فقط.
- جذر React القديم يبقى مخفياً في HOME وTRANSITION، ولا يظهر إلا في INTRO أو GAME.

## فصل الواجهة عن القائمة القديمة
1. `scripts/qarton-isolated-home.js` يبني بطاقات HOME بنفسه؛ لا يبحث عن `.home-actions` ولا ينسخ أزرار القائمة القديمة.
2. `scripts/prepare-web.cjs` يعرّف جسوراً صريحة لبدء الجزء الأول، متابعة الحفظ، بدء الجزء الثاني والجزء الثالث.
3. وظيفة HOME لا تعتمد على ظهور القائمة القديمة أو اكتمال عناصرها؛ يكفي أن يجهز محرك القصة جسور التشغيل.
4. اختيار الصعوبة يستعمل حالياً عنصر تحكم المحرك المخفي كجسر توافق فقط؛ هذا لا يعيد عرض القائمة القديمة.
5. محوّل التنقل الأصلي في Android أصبح مسؤولاً عن أزرار الحفظ والعودة أثناء GAME فقط، ولا يحقن أزرار HOME داخل React.
7. تبقى القصة ومحرك React ومفاتيح الحفظ هي مصدر الحقيقة؛ لا نكرر منطق القصة في واجهة QARTON.

## قواعد السلوك
1. «ابدأ الجزء الأول» يبدأ قصة جديدة، ويطلب تأكيداً إذا كان هناك حفظ سابق.
2. «متابعة آخر حفظ» يظهر عند وجود حفظ، ويستعيد أحدث سجل صالح.
3. «الجزء الثاني» يستدعي جسر محرك القصة مباشرة.
4. «الجزء الثالث» يبقى مقفلاً إلى أن يتحقق شرط نهاية الجزء الثاني.
5. العودة من القصة تحفظ التقدم أولاً؛ عند فشل الحفظ لا تتم إعادة تحميل الصفحة.
6. لا تغيير في النصوص الأصلية أو اللهجة أو الشخصيات أو منطق الاختيارات أو مفاتيح التخزين.

## اختبارات القبول
- اختبار دورة الحالة HOME → TRANSITION → INTRO → GAME → HOME.
- اختبار ظهور بطاقات QARTON دون وجود `.home-actions` في جذر React.
- اختبار Continue مع حفظ موجود، وبداية جديدة مع تأكيد يحافظ على الحفظ السابق.
- اختبار جسر الجزء الثاني، وبقاء الجزء الثالث مقفلاً قبل تحقق الشرط.
- اختبار اختفاء الجذر القديم في HOME وTRANSITION وعدم ظهوره للحظة عند التشغيل.
- اختبار شاشة 360×640 دون تمرير رأسي مع بقاء الزر الأساسي ظاهراً.
- تشغيل `npm test` ثم `npm run prepare:web` ثم اختبار Chromium وبناء APK.
- اختبار اللمس والصوت والحفظ والعودة إلى الرئيسية على هاتف Android فعلي قبل اعتماد الإصدار.
