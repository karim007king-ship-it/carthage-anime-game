# QARTON — مخطط التحويل إلى لعبة أنمي سينمائية تفاعلية

**الحالة:** مواصفة تصميم وتنفيذ، لا تغييرات فعلية على المحرك أو APK.
**المشروع:** «آخر يوم في قرطاج» — 36 فصلًا / ثلاثة أجزاء / تسع نهايات أصلية.
**الفرع:** `docs/astra-carthage-narrative-expansion`.
**الهدف:** تحويل الفصول السردية إلى مشاهد أنمي 2D متحركة جزئيًا، مع إخراج كاميرا وخلفيات وشخصيات وصوت واختيارات، وإعادة تصميم واجهة اللعب دون المساس بالشاشة الرئيسية الرسمية أو الحفظ القديم.

## 1. المبادئ غير القابلة للكسر

1. اللعبة **تفاعلية وسينمائية**، وليست قارئ نصوص أو صورًا ثابتة متعاقبة.
2. الإخراج ثنائي الأبعاد 2D بطبقات متعددة، مع كاميرا افتراضية (pan, zoom, parallax) وتحريك خفيف للشخصيات؛ لا يلزم 3D لتقديم تجربة أنمي.
3. الفصول الـ36 هي بنية سردية، وليست بالضرورة 36 فيديو مستقلًا: كل فصل يتكون من لقطات وبيئات وحوارات وأفعال واختيارات.
4. الحفاظ على اللهجة التونسية والنهايات التسع الأصلية وبيانات التقدم؛ لا إعادة ترتيب مباشرة لفهارس المشاهد القديمة.
5. الإبقاء على هوية QARTON الذهبية/الحمراء/السوداء وعلى المقدمة الرسمية المعتمدة؛ لا استبدال الفيديو أو الواجهة الرئيسية ضمن هذه المهمة.
6. جميع الصور والأصوات أصلية أو مرخّصة، مع سجل للمصدر وحقوق الاستخدام.
7. الجودة السينمائية لا تعني تنزيل ملفات ضخمة دفعة واحدة: أصول قابلة لإعادة الاستخدام وتحميل كسول ونسخ خفيفة.
8. لا دمج على الفرع الرئيسي قبل الاختبارات وتجربة Android والموافقة.

## 2. تقسيم شاشة اللعب — هاتف عمودي أولًا

### A. الوضع العادي: Cinematic Story
- **منطقة العرض البصري:** 52–62% من ارتفاع المساحة الآمنة، بحسب نسبة الشاشة؛ خلفية عريضة داخل إطار قابل للقص الآمن، شخصيات أمامية وطبقات عمق.
- **منطقة الحوار:** 18–25%، بطاقة شبه شفافة فوق الجزء السفلي من الصورة أو تحته بحسب المشهد، اسم المتحدث، نص عربي RTL، زر متابعة ومسجل حوار.
- **منطقة الاختيارات:** عند لحظة القرار فقط، بطاقات كبيرة قابلة للمس، من خيارين إلى ثلاثة، لا تتداخل مع عناصر Android أو شريط الإيماءات.
- **شريط تحكم صغير:** إيقاف/استئناف، صوت، سجل الحوارات، إعدادات، تخطٍ آمن للمشاهد المعادة.
- لا تمرير رأسي في شاشة اللعب الأساسية. عند النص الطويل يُجزأ الحوار إلى وحدات مع زر متابعة، بدل تمديد الصفحة.

### B. الوضع السينمائي: Full Scene
- ملء المنطقة الآمنة بالمشهد؛ إخفاء شريط التقدم والاختيارات والحوار عند لقطات الانتقال.
- تظهر ترجمة/حوار قصير عند الحاجة، وتُستعاد الواجهة بعد انتهاء اللقطة أو تخطيها.
- زر تخطٍ ظاهر بعد مدة قصيرة، مع عدم تجاوز أي قرار لم يُتخذ.

### C. وضع الاختيار: Decision Focus
- تعتيم تدريجي للخلفية مع بقاء الشخصية المهمة مرئية.
- عرض نتيجة متوقعة نوعيًا («الطريق قد يتأخر»)، لا حرق عواقب مخفية.
- توقيف ساعة المشهد البصرية عند الاختيار؛ مؤقت قرارات اللعبة الأصلي يبقى خاضعًا لإعداد الصعوبة وقواعد الإيقاف.
- زر التأكيد يحفظ الاختيار مرة واحدة ثم ينتقل للقطات النتيجة.

### D. الوضع الأفقي (اختياري لاحقًا)
- المشهد على اليسار/الأعلى والحوار في شريط جانبي؛ لا يُنفّذ قبل استقرار الوضع العمودي.

## 3. بنية المشهد السينمائي

كل فصل يتكون من `sequence` ثم `shots`، وكل لقطة تحتوي:
- `background`: موقع/وقت/طقس، 2–5 طبقات للعمق.
- `characters`: معرف الشخصية، موضع، حجم، وضعية، تعبير، حركة بسيطة.
- `camera`: نوع اللقطة، نقطة تركيز، حركة، مدة، easing.
- `audio`: موسيقى أصلية، مؤثرات، صوت بيئي، حوار صوتي إن توفر.
- `dialogue`: متحدث، نص تونسي، إيقاع ظهور، ترجمة حسب اللغة.
- `choiceGate`: اختيار اللاعب، شرط ظهور، تأثيرات اللعبة المؤجلة حتى التأكيد.
- `fallback`: صورة ثابتة/انتقال بسيط عند تقليل الحركة أو ضعف الجهاز.

مثال **مواصفة** غير جاهز للتشغيل:

```json
{
  "storyId": "p3-single-load",
  "sequenceId": "crossroads-opening",
  "shots": [
    {
      "id": "cart-wide",
      "background": "carthage-crossroads-dawn",
      "layers": ["sky", "ruins", "road", "foreground-dust"],
      "camera": { "type": "wide", "pan": "left-to-right", "durationMs": 4200 },
      "characters": [{ "id": "rayan", "pose": "standing", "expression": "worried" }],
      "audio": { "ambience": "wind-harbor", "music": "decision-tension" },
      "dialogue": null
    },
    {
      "id": "lina-closeup",
      "camera": { "type": "closeup", "focus": "lina", "durationMs": 2600 },
      "characters": [{ "id": "lina", "pose": "talk", "expression": "concerned" }],
      "dialogue": { "speaker": "lina", "key": "p3.ch27.lina.firstLine" }
    }
  ],
  "choiceGate": "p3-single-load-choice"
}
```

## 4. نظام الأصول البصرية

### الخلفيات الأساسية
البيت، السوق، الأسوار، الأزقة، دار منصور، المستشفى، الجسر، البوابة، الميناء، المدرسة، العيادة، الرصيف، الساحة، غرفة الجلسة، أطراف المدينة. كل موقع يمكن أن يكون له `day` / `night` / `smoke` / `rain` بدل إعادة إنشاء صورة لكل حوار.

### الشخصيات
ريان، لينا، سارة، يوسف، نور، إيلاس، عم منصور، سليم، مريم، أمين، ياسمين، كريم، الهادي وشخصيات ثانوية. لكل شخصية:
- صورة مرجعية موحّدة للحفاظ على الملامح واللباس والنسب.
- تعابير أساسية: عادي، خوف، حزن، غضب، تصميم.
- أوضاع: وقوف، التفات، كلام، مشي محدود، إصابة عند الحاجة.
- حركة 2D خفيفة: رمش، تنفس، التفات، انتقال بين تعابير؛ لا نعد بتحريك كامل لكل شخصية دون أصول مناسبة.

### مؤثرات
دخان، نار بعيدة، غبار، مطر، أشعة شمس، انعكاس الماء، وميض مشاعل. لا تُعرض مؤثرات عالية الكثافة فوق نص الحوار.

## 6. الصوت والإخراج

- موسيقى QARTON أصلية حسب الحالات: ترقب، فقد، قرار، كشف، أمل؛ لا تُستخدم موسيقى أعمال أنمي محمية.
- مؤثرات بيئية مكانية خفيفة: بحر، رياح، نار، وقع أقدام، جرس، ورق.
- الحوار الصوتي يمكن إطلاقه تدريجيًا؛ النصوص كاملة ومقروءة حتى عند غياب التسجيل.
- تحكم مستقل في مستويات الموسيقى والمؤثرات والحوار؛ دعم كتم الكل.
- توحيد توقيت الكاميرا والشخصيات والمؤثرات عبر ساعة مشهد واحدة في محرك QARTON، دون إنشاء مؤقتات متنافسة.

## 7. المعمارية والدمج

1. تدقيق فعلي لواجهة اللعبة الحالية وملفات العرض ومحرك `qarton-cinematic-engine` قبل تعديلها.
2. إنشاء طبقة `StoryAdapter` تربط معرفات `storyId` الجديدة بفصول القصة الأصلية دون إزاحة `sceneIdx` القديمة.
3. إنشاء `CinematicSceneRenderer` للمشهد، `DialogueOverlay` للنص، `DecisionOverlay` للاختيارات، و`AssetManifest` للصور والصوت.
4. وضع العرض السينمائي خلف feature flag أثناء التطوير؛ لا إلغاء الشاشة الرئيسية الحالية أو كسر زر «لعبة جديدة».
5. حفظ الحالة المنطقية (المشهد/القرار/النتائج) بشكل مستقل عن زمن الأنيميشن؛ استئناف الحفظ لا يكرر الآثار.
6. استخدام ملفات أصول محسّنة مثل WebP/AVIF حيث يدعمها WebView، وتحميل مسبق للّقطة التالية فقط، وتحرير الأصول القديمة من الذاكرة.
7. تجربة أولية بمشهد واحد من الفصل 27 قبل تعميم النظام على 36 فصلًا.

## 8. تجربة Android ومعايير الجودة

- الوضع العمودي أولًا، مناطق لمس لا تقل عن نحو 44–48dp، مراعاة notch وsafe areas.
- هدف مبدئي 30fps على الأجهزة المتوسطة، و60fps حيث يتاح دون التضحية بثبات العرض؛ قياس فعلي لا ادعاء مسبق.
- صورة ثابتة وانتقالات بسيطة عند تقليل الحركة، وعند انخفاض الأداء.
- نص RTL سليم، عدم قطع الحوار، وعدم تغطية الاختيارات بعناصر النظام.
- اختبار تشغيل/إيقاف/استئناف/تخطي/رجوع، تغيير اللغة، بدء لعبة جديدة، حفظ قديم عند الفصل الخامس، العمل دون اتصال، ومغادرة التطبيق أثناء اللقطة.
- فحص استهلاك الذاكرة، وعدم استمرار الموسيقى أو المؤقتات بعد الخروج من المشهد.
- اختبارات المسارات التسعة للنهايات بعد دمج المشاهد، وعدم فتح الجزء الثالث مبكرًا.

## 9. مراحل التنفيذ

**P0 — تدقيق وتثبيت:** مراجعة الملفات الحقيقية وبنية العرض، وتحديد نقاط الدمج وحصر الأصول الحالية، وتثبيت ترتيب الـ36 فصلًا.

**P1 — نموذج سينمائي قابل للعب:** تنفيذ الفصل 27 بمشهد افتتاحي متحرك، شخصيات وخلفية، حوار، ثلاثة اختيارات، حفظ/استئناف، واختبار Android.

**P2 — نظام إنتاج الأصول:** مراجع الشخصيات، مكتبة خلفيات قابلة لإعادة الاستخدام، manifest، قواعد تسمية وترخيص، تحسين الأحجام.

**P3 — تحويل الفصول:** تحويل النصوص إلى shot lists وتطبيق الواجهة على الأجزاء الثلاثة على دفعات، مع اختبار كل دفعة.

**P4 — تدقيق شامل:** اختبارات النهايات التسع والحفظ واللغات والأداء والصوت، ثم دمج تدريجي بعد موافقة المستخدم.

## 10. تعريف الاكتمال

لا يُعتبر «تحويل اللعبة إلى أنمي سينمائي» منجزًا بمجرد كتابة هذه الوثيقة أو إنشاء صور؛ يجب وجود **مشهد يعمل فعليًا داخل APK أو WebView** مع خلفية وشخصيات وحركة كاميرا وحوار واختيارات وحفظ سليم، ثم تكرار ذلك لبقية الفصول بعد نجاح النموذج.
